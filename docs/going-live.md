# Going live checklist

The current Pages deployment uses real-source provisional snapshots, not fixture
demo data. It must remain `noindex` until the release gates below pass. The
current inventory and unresolved approvals are generated by `pnpm release:report`.

Production activation requires approval of every source actually named by the release snapshots; a CDS personal access token stored as a GitHub Actions repository secret; reviewed selected-cell coordinates and model elevations; real sampling/climate snapshots; no seed data; at least 50 destinations; at least 30 operator-approved Golden cases; calibration and anomaly review; complete legal/operator details; image attribution; accessibility/performance QA; custom domain; and a final science/data audit. The current release requires ERA5-Land approval and does not use Copernicus DEM. Any future DEM-backed release automatically requires separate DEM semantics and licensing approval. No Cloudflare Workers Paid plan, Container, Workflow, R2 bucket, or runtime data service is required.

Only after those gates pass should the committed climate snapshots carry `"datasetStatus": "production"` and the public canonical URL be set. That field, surfaced through the manifest, is what `app/robots.ts` and `app/sitemap.ts` read; no environment variable can open the site for crawling.

Human approvals are recorded in `data-config/methodology/release-approvals.json` with approver and timestamp fields. Changing a flag is an operator act, not an automated build step. `pnpm release:report` exposes every unresolved approval as a production blocker.
